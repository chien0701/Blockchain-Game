# 專案總覽

## 1. 這個專題是什麼？

FairChain 是一個**區塊鏈公平遊戲驗證系統**。表面上它是個線上賭場（11 款遊戲），
但真正的主體是底下那套**可公開驗證的公平性協議**——遊戲只是用來展示協議通用性的載體。

## 2. 解決什麼問題？

線上博弈、抽卡、開獎都有同一個結構性問題：

> 玩家下注後，結果由平台的程式決定。玩家**無法驗證**平台有沒有在看到下注後才動手腳。
> 玩家唯一能做的是「相信平台」。

這叫 **信任問題（trust problem）**，而且它不可稽核——作弊可以做得神不知鬼不覺。

## 3. 為什麼需要這個系統？

FairChain 把「你要相信我」換成「**你可以自己算、自己驗**」，靠兩件事：

| 需求 | 區塊鏈提供的性質 |
|---|---|
| 承諾不能事後偷改 | **不可竄改**（寫進區塊鏈就改不掉） |
| 任何人都能查證 | **公開可讀**（全球節點都存著同一份資料） |

再加上密碼學的 **Commit-Reveal 雙盲協議**，做到「雙方都無法單獨操控結果」。

## 4. 系統主要使用者是誰？

| 使用者 | 使用情境 |
|---|---|
| **玩家** | 連接 MetaMask，用測試幣下注遊玩，贏了由合約自動賠付 |
| **驗證者（任何第三方）** | 不需錢包、不需信任本網站，用鏈上 Game ID 獨立驗證某局是否公平 |
| **教學／展示對象** | 透過「說明頁」互動 demo 與「實驗室」理解密碼學與機率原理 |
| **莊家（合約部署者）** | 部署合約、注資金池、可提領未鎖定資金 |

> 註：目前為**單人對莊家（合約）**架構，**沒有多人連線對賭**功能。

## 5. 系統有哪些主要功能？

| 功能 | 路由 | 說明 |
|---|---|---|
| 首頁 | `/` | 專題介紹、運作原理、遊戲陣容（GSAP 捲動動畫） |
| 遊戲大廳 | `/lobby` | 11 款遊戲選擇器、個人遊戲紀錄 |
| 21 點 | `/game/:id` | Commit-Reveal 發牌、Hit/Stand、莊家補牌至 17 |
| 8 款下注遊戲 | `/play/{dice,roulette,slots,crash,limbo,wheel,plinko,revolver}` | 真實鏈上下注 + 合約自動賠付 |
| 猜數字 | `/play/mastermind` | 承諾不可變示範（commit → 猜 → reveal 驗證） |
| 挖礦模擬 | `/play/mining` | PoW／nonce／難度教學（**純本機，不上鏈**） |
| 驗證工具 | `/verifier` | 雙模式：本地紀錄驗證 ／ **鏈上 permissionless 驗證** |
| 說明頁 | `/docs` | 互動式 Commit-Reveal demo、概念詞彙表 |
| 統計 | `/stats` | 勝率、資金曲線（累積淨收益折線圖）、各遊戲分布 |
| 期望值實驗室 | `/lab` | 蒙地卡羅模擬，理論 RTP vs 實測（驗證公平性數學） |

## 6. 使用者完整操作流程

以「玩一局骰子並驗證」為例：

```
1. 開啟網站 → 右上角「連接錢包」→ MetaMask 授權（網路須為 Sepolia）
2. 進入「遊戲大廳」→ 點選「骰子 / 猜硬幣」
3. 選擇注型（大/小/單/雙）+ 用籌碼或自訂欄位設定注金
4. 按「⚡ 下注並直接開獎」（快速模式）
   ├─ 交易 1：placeBet — 注金真的轉入 FairBet 合約，承諾上鏈
   └─ 交易 2：settleBet — 揭露種子，合約驗證承諾、計算 finalRandom、判定輸贏
5. 贏 → 合約自動把賠付轉回錢包（MetaMask 餘額真的增加）
   輸 → 注金留在莊家資金池
6. 結果頁顯示：骰子點數、密碼學證明（finalRandom、兩筆交易 Hash、鏈上 Game ID）
   並標示「✅ 合約判定結果與本地重算完全一致」
7. 點「驗證公平性」→ 或任何人到 /verifier 用鏈上 Game ID 獨立重算驗證
```

**三種執行模式**（系統自動判斷，見 `src/hooks/useBetting.js` 第 53 行）：

| 模式 | 觸發條件 | 行為 |
|---|---|---|
| `bet` | 有設定 `VITE_FAIRBET_ADDRESS` 且已連 MetaMask | 真實下注 + 合約結算 + 自動賠付 |
| `plain` | 只設 `VITE_CONTRACT_ADDRESS` | 僅上鏈公平驗證，無金流 |
| `mock` | 未設合約地址，或使用模擬錢包 | 純前端模擬（無 MetaMask 也能展示流程） |

## 8. 每項技術為什麼被選擇？

完整的技術選型理由與替代方案比較，見 **[TECHNICAL_DETAILS.md](./TECHNICAL_DETAILS.md#技術選型)**。
此處先給最關鍵的三個：

- **Keccak256（而非 SHA-256）**：以太坊原生雜湊，Solidity 與 ethers.js 都內建，
  能保證**前端與合約算出逐位元相同的結果**——這是「任何人可重算驗證」的前提。
- **Commit-Reveal（而非 Chainlink VRF）**：只需一個雜湊函數即可達成雙盲，
  無需預言機與額外費用；且「雙方共同決定」在教學上更能展示互不信任下的公平。
- **Ethereum Sepolia（而非本地 Hardhat）**：本地鏈只有自己看得到，
  等於「相信我沒作弊」，會**推翻專題的核心命題**；公開測試網才能讓第三方獨立驗證。
