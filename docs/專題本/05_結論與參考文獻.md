# 五、結論

## 5.1 研究成果

本專題針對線上博弈長期存在的信任問題，設計並實作了 FairChain——一套以「玩家承諾結合未來區塊雜湊」產生亂數、於結算交易中由智能合約判定與賠付的區塊鏈可驗證公平博弈系統。對照第一章所訂之四項研究目的，成果如下：

**目的一：設計可防止預選的亂數協議並界定其信任假設。** 已完成。玩家僅承諾自己的種子，第二份熵取自下注後才產生之區塊雜湊，在 3.2.4 所列假設下，玩家於投注鎖定時無法預知結果；40 局對抗測試未重現初版之預選攻擊。殘餘風險（玩家與出塊者串通）已明確界定。

**目的二：實現由智能合約執行之結算。** 已完成。`FairBet` v3 支援九種遊戲類型，由合約以純函數 `resolve()` 判定並於結算交易中賠付；期限以區塊高度計算，結算與過期之區間互斥，過期局具獨立狀態；資金池以「餘額 ≥ 鎖定額」之不變量保證償付能力，並經並發下注與提領測試驗證。

**目的三：提供無須許可之驗證機制。** 已完成。v3 將種子、熵與結果寫入儲存區，第三方以單次唯讀呼叫即可取得完整證據，並另向 RPC 取得區塊雜湊比對熵；證據不足時判為「未完成」而非「通過」。另提供不依賴網站之命令列驗證工具。

**目的四：以多種玩法驗證架構通用性並量化佐證。** 已完成。v3 已部署至 Sepolia，有效樣本 38 局完整流程實測中 37 局完成、完成之 37 局中 37 局通過以另一 RPC 節點之獨立驗證，模擬中斷 3 次中 2 次恢復結算（失敗原因為 RPC 節點未同步，見 4.7.1）。共 112 項自動化測試於部署前執行；合約測試直接載入前端結果引擎與 Solidity 比對；單局約 31.3 萬 gas；Slither 之 `weak-prng` 警示對應已界定之風險；蒙地卡羅實驗顯示各規則之 RTP 接近理論值，並明確區分「規則分布正確」與「協議防作弊」兩類主張。

## 5.2 主要貢獻

本專題屬整合應用：亂數協議之結構、賠付鎖定、押金懲罰與 Crash 倍率函數等均沿用既有方法（出處見表三）。本專題之貢獻在於下列整合、修正與實證：

**（一）系統整合與實作。** 採用既有之承諾－揭露機制、未來區塊雜湊與智能合約安全設計模式，整合完成 FairChain 之遊戲操作、鏈上結算與第三方驗證功能；並依「結果能否由公開參數與 finalRandom 確定性計算」及「是否含須於玩家行動期間保密之資訊」分類遊戲，將九種遊戲上鏈結算，二十一點與猜數字定位為公平性展示。所採用之既有技術、程式位置與分工見第二章與表三；程式係在 AI 程式開發工具協助下撰寫（2.7）。

**（二）協議缺陷修正與回歸測試。** 初版可於下注前預選結果之缺陷由助教以本機對抗測試指出；本專題依既有亂數設計方法 [29][31] 完成 v3 之修正與驗證（3.2），並將該反例轉為永久回歸測試，另以 v2 與 v3 之 Slither 結果對照，說明靜態分析無法偵測此類協議層缺陷。

**（三）系統驗證與實測。** 完成前後端一致性測試、五項證據之驗證器、Sepolia 測試網實測、Gas 分析與蒙地卡羅模擬，確認系統於所列測試範圍內之功能表現，並說明其安全與成本限制（4.8.4）。

## 5.3 研究限制之回顧

詳見 4.8.4：

- 出塊者串通風險
- 重組未自動處理
- 未完成 Etherscan 原始碼驗證
- 主網成本與 L2 之亂數假設差異
- 二十一點與猜數字不防作弊
- 種子遺失即無法結算
- 合約端取模之理論偏差
- 未經專業審計

此外，各遊戲賠率表未統一校準（拉霸 RTP 達 105.56%、輪盤單一號碼僅 81.08%），已於 4.8.3 記錄。

## 5.4 未來工作

依優先順序：

1. **完成 Etherscan 原始碼驗證**（目前以逐位元組比對證明對應）。
2. **改用 VRF 後移至 L2**：鏈的比較（`docs/CHAIN_COMPARISON.md`）顯示 L2 之 blockhash 不可作為安全亂數來源 [24]。
3. **同條件比較實驗之 L2 與 VRF 部分**：L1 已完成（4.7.1），以相同腳本比較 L2 及 Chainlink VRF [13]。
4. **重組處理**：偵測開獎區塊被替換並自動重新結算。
5. **校準賠率表**：方差與尾端分析已完成（4.8.3），下次重新部署時一併修正。
6. **隱藏資訊遊戲之協議**：二十一點逐張揭露或引入獨立莊家。
7. **專業安全審計與形式化驗證。**
